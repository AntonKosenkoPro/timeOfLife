# Activity Catalog & Categories — FURPS

Requirements for the **Activity Catalog & Categories** feature. This feature turns the MVP's free-text timer into a structured, reusable catalog of activities and category tags, and surfaces recency-based suggestions on the timer screen.

App-wide requirements (minimalism, dark/light, offline, EN+RU localization, HIG, secure storage, linters, tests, CI, OpenAPI, `AGENTS.md`) live in [`Common.md`](./Common.md) and are not repeated here; only feature-specific rows are listed.

| Index | Requirement                                                                                                                                                             | Comment                                                                                                                                                                                                               |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1    | Create, edit, and delete **activities**. An activity has a name, optional notes, and zero or more category ids.                                                        | Replaces the MVP's throwaway free-text `activityName`; category-derived representation is resolved from the synced catalog. Track currently has no editing affordance (removed during refine-track-recents; editing stays available from Manage Activities).                            |
| F2    | Create, edit, and delete **categories** from Profile's Manage Categories destination. A category has a validated name and a catalog SF Symbol icon.                                  | A many-to-many tag layer; an activity may carry zero or more category tags. The local catalog remains usable signed out and offline.                                                                                 |
| F3    | Tag/untag an activity with one or more categories.                                                                                                                      | Tags are optional; an activity with no tags is valid (ad-hoc / uncategorized tracking remains possible).                                                                                                             |
| F4    | Starting a timer by entering a name that matches no existing activity **auto-creates** a new activity and links the entry to it.                                          | Name matching is case-insensitive and trims surrounding whitespace; a matching existing activity is **reused** (no duplicates). The auto-created activity has no categories; categories can be assigned later. Creation rechecks identity at confirmation time through the atomic local create-or-resolve operation (unify-activity-preparation-flow). |
| F5    | The Track screen shows **Recents**: the user's up-to-6 most recently used activities, computed **on-device** from the local catalog.                                  | No server endpoint: the client ranks its synced activities by `last_used_at` and takes the top 6 (works fully offline). One tap prepares the Activity (ready state) and links it to the upcoming entry. Recents is a wrapping chip flow (no horizontal scrolling) hidden while the timer is running; chips show the icon of the first assigned Category only, and the prepared Activity's chip uses a filled accent highlight (refine-track-recents). |
| F6    | On first local-dataset setup, a **default starter set of 7 categories** is seeded exactly once, localized in EN and RU.                                          | Categories: Work, Hobby, Sport, Education, Relax, Sleep, Entertainment. A durable local marker prevents reseeding after user deletion; erase-local-data clears the marker. No starter activities are seeded. Seeds are ordinary records — fully editable and deletable. |
| F7    | The **Activity search** on Track lets the user create a new activity by name only without leaving the timer. Track currently shows **no editing affordance**.                                 | Platform-native search (unify-activity-preparation-flow): the operating system owns placement, focus, keyboard, and Cancel. Unmatched valid input offers one quick-create action (categoryless); configured creation is not offered in search. The former beside-picker Refine action was removed during refine-track-recents; the editor sheet machinery stays wired for a later placement decision, and activities remain editable from Manage Activities. |
| F8    | A full **Manage Activities** screen lists all activities (and their categories), with edit and delete. Category CRUD is provided by a separate Manage Categories screen. No manual reorder at MVP.                  | Reached from Profile. The list is ordered by most-recently-used (recency); Track suggestions show Activity names only and are also recency-ranked. |
| F9    | Entries reference an activity by `activity_id`; the activity's category tags are inferred by the entry at query time.                                                   | The OpenAPI spec (`backend/api/openapi.yaml`, S10) and the offline sync contract are updated for `activities`, `categories`, and the `activity_id` field on entries. The activity's name and tags are resolved from the activity at query time (nothing is denormalized onto the entry). |
| F10   | Deleting an activity that has past entries prompts the user to choose the scope: **delete the entire activity (and all its entries)**, or **delete only the current entry**. | The prompt clearly states how many entries are affected. Both choices are destructive and trigger the undo flow (R3).                                                                                                 |
| F12   | Activities and categories are **synced across devices** and available offline.                                                                                          | CRUD performed offline is queued locally and synced when connectivity returns (D7).                                                                                                                                   |

| U7    | **Shake-to-undo** (iOS system Undo gesture) restores the most recent undoable category deletion while Manage Categories is active.                                  | Uses the system motion event and `UndoManager`; app-wide activity/history adoption remains deferred.                                                                                                                                                                            |

| U9    | All user-facing strings use `L10n.*` keys (EN + RU); visual tokens use `Theme.*`; native SwiftUI components only; stable `accessibilityIdentifier`s on every control. | Common U2/U4/U5 and design decisions D3/D4/D6.                                                                                                                                                                         |
| R1    | Activity/category CRUD is **offline-first**: works with no connectivity and syncs on reconnect.                                                                        | Design decision D7 / Common U3.                                                                                                                                                                                       |
| R2    | Sync conflicts (same activity edited on two devices) resolve by **last-write-wins on `updated_at`**.                                                                    | The most recent write per record wins; no field-level merge at MVP.                                                                                                                                                |
| R3    | Deletions are **atomic and undoable**: a deletion is held in a client-side undo buffer and is not committed to the local store or pushed to sync until the 30 s undo window passes (or the buffer is superseded by the next undoable action / relaunch). | Shake-to-undo re-inserts from the same buffer. [^1]: The auto-created activity is a first-class record: it appears in suggestions next time and can be edited to add categories. The user is never forced to open the catalog to start a timer — creating a name in the search and starting still works in one step (F4).

## Resolved decisions

- **Sync conflict policy** (R2): last-write-wins on `updated_at`; no field-level merge at MVP.
- **Seed set** (F6): 7 categories — Work, Hobby, Sport, Education, Relax, Sleep, Entertainment (EN/RU). No starter activities.
- **Limits**: no count caps enforced at MVP; name ≤ 60 chars, notes ≤ 280 chars.
- **Manage Activities ordering** (F8): no manual reorder at MVP; list is recency-ordered (most-recently-used first).
