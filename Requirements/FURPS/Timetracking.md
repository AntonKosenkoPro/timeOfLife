# Timetracking — FURPS

Requirements for the **local-first sync architecture** (OpenSpec change `local-first-sync-architecture`): the device is the source of truth, the backend is an optional relay, and sync is a transport feature that activates on sign-in — not a prerequisite for using the app. The app launches into the Track shell without requiring sign-in; auth is an optional "Enable Sync" action in Profile.

App-wide requirements (minimalism, dark/light, offline, EN+RU localization, HIG, secure storage, linters, tests, CI, OpenAPI, `AGENTS.md`) live in [`Common.md`](./Common.md) and are not repeated here; only feature-specific rows are listed.

| Index | Requirement                                                                                                                                                             | Comment                                                                                                                                                                                                               |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1    | The **local device is the source of truth**: activities, categories, entries, and the running timer state live in a local SQLite database (GRDB) in the App Group shared container (`group.com.antonkosenko.timeoflife`). All app features work fully with no network connectivity and no signed-in account. | The backend is an optional relay, not the authority. The database is accessible cross-process (widgets, Screen Time extension, lock-screen Control intents) and after first-unlock-since-boot (`.completeUntilFirstUserAuthentication`). |
| F2    | Every local mutation (create, update, delete) writes the state change **and a transactional outbox row in one transaction**. Deletes are first-class (the outbox row persists after the record is gone). The outbox survives relaunch. | Each outbox row maps to one idempotent POST / LWW PATCH / hard DELETE on the relay. `LocalStore` is the single chokepoint for all mutations — no raw GRDB writes outside it. |
| F3    | Deletions enter a **durable undo buffer** (full serialized snapshots) and remove the records in one transaction; the 30 s window is **wall-clock** (`deleted_at + 30s`), not a `Timer`. No outbox row is created while a deletion is in the buffer. | Expired buffers commit on the **next foreground** (never in the background; no background timer). The buffer survives suspension, kill, and cold launch. Supersession per U7: only the most recent undoable deletion is restorable; older ones commit when their own window elapses. |
| F4    | The **running timer state** (`activity_id`, `started_at`, `status`) is persisted in a `timer_state` singleton row in the local database, not just in memory. | The running timer survives app crashes; widgets and lock-screen Controls read the same row to render running state and elapsed time. |
| F5    | **Sync is optional and gated on sign-in**: the `SyncController` activates on `.signedIn` and deactivates on `.signedOut`. Unsigned users make no sync network traffic; the outbox accumulates locally. | Sync is the paid feature; the app is fully usable without it. Sign-out preserves local data and the outbox; an explicit "Erase local data" action in Profile wipes them. |
| F6    | **First-sync is pull-first**: on activation, pull the relay's full state, merge server-wins on `updated_at` conflicts, then drain the local outbox. | Lets the relay's ids arrive before local pushes, so cross-device name collisions mostly resolve during merge rather than on push. |
| F7    | **Delta pull-sync** via `?modified_since=` (RFC 3339) on `GET /activities` and `GET /entries`; the client advances a per-resource cursor to the max `updated_at` received. | Absent/empty `modified_since` = full pull. Integrations (hundreds/thousands of entries) don't force full re-pulls. |
| F8    | **Last-write-wins conflict resolution on `updated_at`**: on pull, apply a server record only if `server.updated_at > local.updated_at`; on push, 409 `conflict` → adopt the server version (keep-latest) and clear the outbox row. 409 `activity_exists`/`category_exists` → re-map local references to the winning id. | Outbox drain is idempotent (one HTTP call per row, in `created_at` order); replays after crash/relapse are safe. |
| F9    | **Sync triggers**: app enters foreground, connectivity restored (`.satisfied`), and manual "Sync now". A "Last synced"/"Syncing…"/error status is visible in Profile when signed in. | No background task scheduling on iOS (unreliable); macOS may add a timer-based background sync later. |
| F10   | **Entry provenance**: every entry carries `source` (enum: `manual`, `widget`, `siri`, `control`, `screentime`, `garmin`, `calendar`, `healthkit`; default `manual`) and nullable `source_ref` (external id, e.g. Screen Time callback uuid, Garmin activity id). | Persisted locally and propagated through the outbox and relay. |
| F11   | **Duplicate import prevention**: `UNIQUE(user_id, source, source_ref)` for non-null `source_ref`; a source re-sending the same record (Screen Time firing twice, Garmin re-sync) is rejected with 409 `duplicate_import`. | Deleting an imported entry is a hard delete; a later re-import of the same `(source, source_ref)` does not resurrect it. |
| F12   | **Lock-screen Controls** (iOS 18+): a WidgetKit `ControlWidget` toggle starts/stops the timer from the lock screen, Control Center, or Action button without opening the app or Face ID, via an `AppIntent` with `authenticationPolicy = .alwaysAllowed` writing to the App Group database. | Default action: toggle the most-recently-used activity. Availability-guarded (`if #available(iOS 18, *)`); absent on iOS 15–17; deployment target stays 15. Control-started entries carry `source='control'` and enqueue an outbox row in the same transaction. |
| U1    | **User-visible source labels**: non-`manual` entries show a localized "via <Source>" label in entry detail/history; `manual` shows nothing. | Localized in EN and RU (Common U4). |
| U2    | **Sync status is visible**: Profile shows "Last synced: <relative time>" or "Syncing…" (button disabled while in progress) or an error state (button stays enabled to allow retry), visible only when signed in. | The manual "Sync now" action calls the same drain+pull path as the automatic triggers. |
| R1    | The **undo buffer survives the iOS lifecycle**: suspension, kill, and cold launch. The 30 s window is wall-clock; expired buffers commit on the next foreground, never in the background. | Fixes the in-memory buffer bug (a `Timer` dies with the process; the wall-clock check does not). |
| R2    | The **running timer survives app crashes**: on next launch the app reads `timer_state` from the database and resumes the running-timer UI. | Also readable by widgets and Controls cross-process. |
| R3    | **No authentication on the Control intent**: the intent runs with `alwaysAllowed` when the device is locked, without Face ID/Touch ID/passcode. | The intent writes only to the App Group database; no account or token is involved. |
| R4    | **Graceful failure when the database is inaccessible**: a Control intent that cannot open the database (cold boot, never unlocked since boot) returns a "please unlock" state — no crash, no partial write. | `.completeUntilFirstUserAuthentication` keys are evicted until first unlock; the realistic lock-screen case (unlocked at least once since boot) works. |
| S1    | New backend additions are **additive only**: `?modified_since=` on `GET /activities` and `GET /entries`, and `source`/`source_ref` + the unique constraint on `entries` (migration). Auth, CRUD, LWW, idempotent POST, error envelope, and OpenAPI shape are unchanged. | OpenAPI spec bumped to v1.2.0 (Common S10). Existing tests stay valid; new tests cover `modified_since` and provenance. |
| S2    | Unit tests cover the GRDB `LocalStore`, the `UndoBufferStore` (wall-clock window, commit-on-foreground, supersession), and the `SyncController` (pull-first, delta pull, LWW, conflict handling, triggers). | Common S3; logic-layer ~100%. |
| S3    | `AGENTS.md`, `README.md`, `Design/INTERACTIONS.md`, `Design/BACKEND/Activity_Catalog_API.md`, and `backend/api/openapi.yaml` are updated for the local-first architecture. | Common S5/S7. |
## Resolved decisions

- **Local store** (D1): GRDB.swift in the App Group shared container `group.com.antonkosenko.timeoflife`, data protection `.completeUntilFirstUserAuthentication` (default). SwiftData (iOS 17+ only) and Core Data rejected.
- **Outbox** (D2): a separate `outbox` table holding operations (op, resource, record_id, payload, created_at), not a per-record `sync_state` column (deletes would need a tombstone table).
- **Undo buffer** (D3): durable `undo_buffer` table with wall-clock window; commit-on-foreground; no background timer. In-memory + background task rejected (unreliable, doesn't survive kill).
- **First-sync** (D4): pull-first (full pull + server-wins merge, then drain the outbox). Push-first rejected (409 name-collision remapping during push is more complex).
- **Backend additions** (D5): additive only — `modified_since` query param + nullable `source`/`source_ref` columns; no contract break.
- **SyncController** (D6): `@MainActor`, long-lived, optional, session-gated; observes `SessionStore` and `Connectivity`; exposes `@Published status`.
- **RootView** (D7): always shows the app shell (Track/History/Insights); auth is a Profile action ("Enable Sync"), not a launch gate.
- **Running timer state** (D8): `timer_state` singleton row in GRDB.
- **Lock-screen Controls** (D9): iOS 18+ `ControlWidget` + `alwaysAllowed` AppIntent; availability-guarded; deployment target stays 15.
- **Source labels** (D10): user-visible localized "via <Source>" labels for non-`manual` sources.
