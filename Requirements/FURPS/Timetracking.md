# Timetracking — FURPS

Requirements for the **account-bound local-first sync architecture** (OpenSpec change `account-bound-local-data`): the device is the source of truth, the backend is the identity + sync relay, and **sign-in is mandatory** before any tracking use — the app shows a restoring splash while the launch session restore resolves, then the auth flow (email-OTP or Sign in with Apple), then works fully offline. There is no anonymous use: local data is per-account (`lifio_<userId>.db`, one active file, dormant files kept), sessions are per-device, and sync is same-account-only.

App-wide requirements (minimalism, dark/light, offline, EN+RU localization, HIG, secure storage, linters, tests, CI, OpenAPI, `AGENTS.md`) live in [`Common.md`](./Common.md) and are not repeated here; only feature-specific rows are listed.

| F1    | The **local device is the source of truth**: entries, categories, and the running timer state live in a **per-account** local SQLite database (GRDB) in the App Group shared container (`group.com.antonkosenko.timeoflifeapp`) — `lifio_<userId>.db`, one file per account, one active file at a time (active marker keyed on `user_id`). Starter categories seed **per account file** on first open. After the mandatory sign-in, all app features work fully with no network connectivity. Dormant (non-active) account files are kept: logout keeps them, re-login as the same account reopens and resumes (outbox drains, cursors continue, timer draft resumes). | The backend is the identity + sync relay, not the authority. | F2    | Every local mutation (create, update, delete) writes the state change **and a transactional outbox row in one transaction**. Deletes are first-class (the outbox row persists after the record is gone). The outbox survives relaunch. | Each outbox row maps to one idempotent POST / LWW PATCH / hard DELETE on the relay. `LocalStore` is the single chokepoint for all mutations — no raw GRDB writes outside it. |

| F4    | The **running timer state** (`activity_text`, `category_ids`, `started_at`, `status`) is persisted in a `timer_state` singleton row in the local database, not just in memory. | The running timer survives app crashes; the app mirrors the run to a Live Activity from its own process (no extension database reader). |
| F5    | **Sync is session-gated and same-account-only**: the `SyncController` activates on `.signedIn` and deactivates on `.signedOut`; it records the bound `userId` at activation and refuses/skips cycles on account mismatch — it never pushes one account's outbox under another account's token. Sync is not optional for use of the app (sign-in is mandatory), but the tracker works fully offline once signed in. | Sign-out keeps every account file (Keychain/cache/session cleared, DBs untouched, dirty outbox and a running timer stay in the dormant file); an explicit per-account "Erase local data" action deletes only the active account file. |
| F6    | **First-sync is pull-first**: on activation, pull the relay's full state, merge server-wins on `updated_at` conflicts, then drain the local outbox. | Lets the relay's ids arrive before local pushes, so cross-device name collisions mostly resolve during merge rather than on push. |
| F7    | **Delta pull-sync** via `?modified_since=` (RFC 3339) on `GET /entries`; the client follows relay pagination (`limit` + `cursor`/`next_cursor`) to exhaustion on every pull and advances the entries cursor to the max `updated_at` over ALL pages received — never to a partial-page max. Integrations (hundreds/thousands of entries) don't force full re-pulls. |
| F8    | **Last-write-wins conflict resolution on `updated_at`**: on pull, apply a server record only if `server.updated_at > local.updated_at`; on push, 409 `conflict` → adopt the server version (keep-latest) and clear the outbox row. 409 `category_exists` → re-map local references to the winning id. | Outbox drain is idempotent (one HTTP call per row, in `created_at` order); replays after crash/relapse are safe. |

A "Last synced"/"Syncing…"/error status is visible in Profile. | No background task scheduling on iOS (unreliable); macOS may add a timer-based background sync later. The user is always signed in (mandatory gate), so no signed-out pull state exists; offline pulls show an inline offline banner (no cycle); pull-awaited failures show an OK-only dialog. |
| F10   | **Entries carry no producer provenance (retired integrations)**: entries own only `activity_text`, ordered `category_ids`, and `notes`; there is no `source`/`source_ref` in the local shape, outbox payloads, or relay DTOs. ## Resolved decisions

- **Local store** (D1): GRDB.swift in the App Group shared container `group.com.antonkosenko.timeoflifeapp`, data protection `.completeUntilFirstUserAuthentication` (default). SwiftData (iOS 17+ only) and Core Data rejected.
- **Outbox** (D2): a separate `outbox` table holding operations (op, resource, record_id, payload, created_at), not a per-record `sync_state` column (deletes would need a tombstone table).
- **Undo buffer** (D3): durable `undo_buffer` table restorable until restart; commit-on-cold-launch; no background timer. A wall-clock expiry window was tried and removed (it expired before users found the shake gesture).
- **First-sync** (D4): pull-first (full pull + server-wins merge, then drain the outbox). Push-first rejected (409 name-collision remapping during push is more complex).
- **Backend additions** (D5): additive only — `modified_since` query param; no contract break.
- **SyncController** (D6): `@MainActor`, long-lived, session-gated; observes `SessionStore` and `Connectivity`; exposes `@Published status`; records the bound `userId` and refuses cycles on account mismatch.
- **RootView** (D7): gates on `SessionStore` — restoring shows a splash (never the auth flow), signed-out renders the auth flow full-screen, signed-in renders the app shell only after the account file is bound, buffered deletions committed, and starter categories seeded (seed-before-reveal; first-sync pull stays background and Track converges via its sync-exit reload). Anonymous use is removed; auth is the launch gate, not a Profile action.
- **Running timer state** (D8): `timer_state` singleton row in GRDB.
- **Lock-screen Controls** (D9): retired, not deferred — no `ControlWidget`, no background intent, no extension database writer. The iOS 18 deployment floor stands on its own (app-shell).
- **Account-bound store** (D11): per-account files `lifio_<userId>.db` (one active at a time, active marker = `user_id`); dormant files kept, no eviction; per-account seeding on first open; explicit per-account Erase deletes only the active file; per-account data migration rejected (pre-release discard).
- **Per-device sessions** (D12): stable Keychain UUID as `X-Device-Id` (not `identifierForVendor`); per-device refresh families; reuse-detection and logout revoke only that device's family; refresh TTL enforced at the refresh handler; revoked/exhausted sessions lock to the auth gate — never wipe (lock-not-wipe). No `device_limit` in the API (quota + picker deferred to #46); no multi-session switcher (every switch re-authenticates).
- **Source labels** (D10): retired — no producer labels in any locale; History rows and the entry form show the entry's own values only.
